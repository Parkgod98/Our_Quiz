## 22:28 — 일반 멤버 풀이 404, 조회 성능, 입력 UX 개선

### 작업한 내용
- 스터디 운영자가 아닌 일반 멤버가 배정된 문제집의 `풀기`를 눌렀을 때 404가 나는 경로를 전용 `get_playable_question_set` RPC로 교체함.
- 해당 RPC는 현재 사용자의 그룹 멤버십과 문제집 배정을 명시적으로 확인하고, 정답을 제외한 풀이용 문제 데이터만 한 번에 반환함.
- 홈의 여러 개 Supabase 조회를 `get_dashboard_overview` 단일 집계 RPC로 축소함.
- 스터디 목록의 멤버 수/문제집 수 계산을 `get_my_group_summaries` 단일 RPC로 축소함.
- 스터디 상세는 선택한 탭에서 쓰지 않는 문제집/풀이 기록/프로필 조회를 생략하도록 변경함.
- `group_members(user_id, joined_at)`, `attempts(user_id, updated_at)`, `attempts(group_id, submitted_at)`, `questions(version_id, order_index)`, `question_sets(owner_id, week_number)` 인덱스를 추가함.
- 로그인/회원가입/비밀번호 초기화 폼을 실제 `<form>` 제출로 바꿔 Enter 키로 실행할 수 있게 함.
- 문제 JSON Import에 클릭 선택과 함께 드래그앤드롭을 지원하고 드래그 중 시각 피드백을 추가함.
- 일반 멤버가 배정 목록 조회뿐 아니라 실제 풀이용 문제 데이터 조회와 Attempt 시작까지 가능한지 E2E 범위를 확장함.

### 이유
- 기존 `/quiz/[versionId]`는 문제 버전과 문제를 중첩 RLS 조회한 뒤 그룹 배정을 다시 조회해 일반 멤버 경로에서 404로 떨어질 여지가 있었음.
- 홈은 인증 확인 뒤 여러 테이블을 병렬 조회하면서 전체 답안 데이터를 가져와 집계했고, 스터디 목록/상세도 화면에서 쓰지 않는 데이터까지 조회해 네트워크 왕복과 DB 작업이 과했음.
- 운영 DB의 실제 실행 계획을 직접 측정할 권한은 없으므로 특정 쿼리가 몇 ms 느리다고 단정하지 않고, 코드상 명확한 다중 왕복과 인덱스 공백을 우선 줄임.
